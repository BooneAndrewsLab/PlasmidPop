#300 · a modeless primer workspace and a slim sidebar · mockups

Static HTML, no dependencies. Each file has a desktop frame (1250 × 740) and a phone frame (390 px). The theme toggle follows the app's light and dark tokens; the workspace pages switch from the rail; the Design and Results files have a split / strip layout toggle.

  1. sidebar.html — the slim Primers tab: selection + Design primers…, quick check, primers on this document, My primers…. No settings preview. Plus the empty state and the phone subtab.
  2. design-page.html — the workspace on Design, map live beside it (split) or above it (strip); settings closed with the changed-summary line; the #299 target option.
  3. results-page.html — the dense table with a detail pane, pair 2 shown on the map, the #298 column and action.

Layout: split or strip
Map The map pane the user already has, at the width the splitter leaves it (≥ 280 px); the sequence pane yields while the workspace is open and comes back when it closes. Circular stays circular. A linear ribbon of the whole document across the top, ~84 px. Every position reads left to right, but a circular document is unrolled and the ribbon is a renderer the app does not have.
Workspace ~900 px of 1250 at the sidebar's place; wide enough for the table (≈ 700 px with two 20-mers); detail pane under the table; the width is the existing splitter's. Full width; the detail pane fits beside the table. Nothing else is visible: the selection on the sequence, cut sites, the feature list.
Short window (≤ 500 px high) Rail to icons; map pane stays; nothing stacks. The strip costs 84 px of 400; it has to fold, and then the map is gone.
Phone Full-screen either way; a foldable 60 px strip at the top keeps "where it lands" without a second map. Recommend the strip here only.

Recommendation: split on desktop, with the workspace taking the sidebar's grid column widened to max(560px, 62 %) and the user's splitter position remembered as primers.workspaceWidth; the phone and a short-and-narrow window (note 106's SHORT_WINDOW_QUERY) get the full-screen variant with the foldable strip. Only one new renderer (the strip) and only where there is no room for the real map.

Open questions / decisions for the maintainer
Escape The workspace is a region, not a dialog: no focus trap, no backdrop. Esc closes it only while focus is inside it and nothing inside consumes it first (an open menu, the filter box with text, a textarea selection). Focus returns to the sidebar's Design primers… button. Esc with focus on the map keeps the map's own meaning (clear selection) and leaves the workspace open. Esc never closes it (close only by ✕ / the sidebar tab) — safer for a page the user filled in, but every other panel in the app answers Esc.
Tab order DOM order: toolbar → views → workspace (top bar, rail as a tablist with ↑↓ between pages, then the page) → sidebar tab rail → status bar. Opening it moves focus to the active page's heading (tabindex=-1); the page remembers its own focus when the user comes back from the map. Open onto the primary button (Design) or the table (Results) instead of the heading.
Clicking the map Design: the target follows the selection live, as the tab does today. Results: a map click that changes the selection hides the preview but keeps the selected row (its Show on map unticks); a note Target changed — Design again appears when the selection no longer matches the designed target. The results themselves stay until the sequence changes (as today). Lock the selection while Results is open (rejected: the map must stay live). Or clear the results when the selection changes (rejected: throws work away).
Other sidebar tabs The sidebar tab rail stays visible at the far right. Clicking another tab closes the workspace and shows that tab's panel at the normal width; the Primers tab shows the slim panel with Last design · 10 pairs ›, which reopens the workspace on Results with everything kept (table sort, filters, selected row, settings disclosure state). primers.workspace in panel memory remembers open / page. Keep the workspace open and let the other tab's panel slide in beside it (two panels, too wide). Or a workspace per tab (CRISPR, Cloning) later, with the same shell.
Window size ≥ 1000 px wide: split, map ≥ 280 px, workspace ≥ 560 px, splitter between them. 601–1000 px: full width with the foldable strip. ≤ 600 px (phone): full screen, rail becomes the horizontal page tabs, bar hidden. Short (≤ 500 px high): rail to icons, strip folded by default, settings closed. Stack the map above the workspace between 601 and 1000 px as the views already stack there (VIEWS_STACKED_QUERY) — costs the table its height.
Phone entry The phone shell has no Primers tab today (note 93: a reader). Add Primers as a fourth Details subtab with the slim panel; Design primers… opens the full-screen workspace. Leave the phone as a reader and show only the quick check and My primers there.
Design page density Target chooser (selection / feature / gene), closed settings, one primary button, last-design line. Nothing else. The flank windows are drawn on the map instead of explained. Show the settings open on the first visit.
